# 0.2.1 俄汉词库扩充验证

日期：2026-10-14。

## 问题与修复

用户截图选择 `статистические`，0.2.0 的卡片提示本地词典未收录。核对实际安装包所用的词库后发现：

1. 上游 Kaikki 按语言名分为“俄语”和“俄語”两份分区。0.2.0 仅导入后者，遗漏 `статистический`、`экономический`、`слово` 等大量词条。
2. 原始维基词典没有为每个词提供完整变形表。例如已有 `читать`，但 `читает` / `читают` 缺少可用索引。

0.2.1 同时导入两份源数据，明确用 `lang_code=ru` 过滤合并，并用 OpenCorpora 的实际词典范式扩展已有中文词条。只有范式的原形与词条匹配时才生成索引；不运行词尾预测，不生成中文义项。

- 有中文释义的词条：17,383 → **95,604**。
- 词形索引键：71,489 → **1,373,925**。
- 分片：256 → **1,024**，保持按需读取，避免大词库变成启动或首次查询的整库开销。
- 输入、数据包和构建读取器全部固定 SHA-256，见来源元数据。运行时不依赖 Python、DAWG 或系统二进制。

## 自动化检查

27 项 JavaScript 测试和 5 项 Python 测试通过，覆盖：

- 截图词及多个形容词、动词、名词和代词变形的实际中文结果。
- `стали` 保留 `сталь` / `стать` 等多个原形；`мыло` 不错误扩展出 `мыть` 的变位。
- 合并两个语言名分区，处理未知词性及原始列表标记，不产生空的 ё 别名。
- 遍历全部 1,280 个英俄分片，核对 Python / JavaScript 散列路由、词形引用、中文释义和来源标题。
- 缓存、并发读取合并、失败重试、关闭插件和快速切换等原有行为。

构建和测试：

```sh
python3 scripts/download_sources.py
python3 scripts/build_dictionary.py
npm test
python3 -m unittest discover -s tests -p "test_*.py"
python3 scripts/package.py
```

## 客户端与性能

原生检查在工作区独立配置、空文献库中加载未修改的 XPI。除了原来的英俄查询，还检查 `статистические`、`читает` 和 `экономического` 的真实 DOM 释义；CI 在 Intel / Apple Silicon Mac 上运行同一检查。实际结果见[对应提交的 Actions](https://github.com/vbcnft59/zotero-quicklex/actions)。

这属于程序触发已注册选词回调的客户端检查，没有模拟实际 PDF 上的物理双击或穷尽不同文档、其他插件共存情况。

[基准报告](benchmark-0.2.1.json) 使用扩充后的词库，俄语 13 词、英文 20 词。Node.js 俄语空插件缓存查询中位数 3.487 ms、P95 5.594 ms，缓存查询中位数 0.003 ms。系统磁盘缓存可能已热；不包含 XPI 解压、Zotero 原生弹窗、DOM 和屏幕绘制，不代表完整双击延迟。
